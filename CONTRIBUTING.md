# Contributing to Kiln

Kiln is open source, but it isn't really open to contributions. One person at Enso Dynamics maintains it.

Kiln runs other people's code changes unattended, with their credentials, on their machines. Every part of it is tuned against the Enso Method skills it drives and against real work, and a change that looks small can affect billing checks, completion checks or what an agent is allowed to do. Reviewing someone else's change properly means understanding the problem they hit, working out what else the change would affect, and usually a round of back and forth. I don't have the time to do that well, and doing it badly helps no one.

- **Fork it freely.** The [MIT License](LICENSE) lets you change it however you like, including at work and in commercial products. If Kiln doesn't fit how you work, a fork is the right answer. Please give a fork its own name rather than calling it Kiln.
- **Issues and feedback are welcome,** especially a phase Kiln marked done that wasn't, a check that stopped work for no good reason, or a Claude Code or Codex version that broke something. Use the [bug report](https://github.com/EnsoDynamics/kiln/issues/new?template=bug-report.yml) or the [feedback or question](https://github.com/EnsoDynamics/kiln/issues/new?template=feedback-or-question.yml) form. I read them when I can, but I can't promise a reply or a fix.
- **Pull requests** are generally not accepted, so don't expect a review or a response. If you open one anyway, keep it small and explain the problem it solves. If I take the idea, I may write the change myself rather than merge yours.

Report a suspected security vulnerability privately, as [SECURITY.md](SECURITY.md) describes, never in a public issue.
