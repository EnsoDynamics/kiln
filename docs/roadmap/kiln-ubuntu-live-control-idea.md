# Kiln idea: Ubuntu live messages and safe terminal takeover

**Roadmap:** [Kiln roadmap](../kiln-roadmap.md).

**Origin:** Captured 2026-10-27 at Doug's request as context for a future change PRD.

**The use case.** Kiln controllers may run on both a Mac and a remote Ubuntu workstation. The person reaches Ubuntu through AWS Systems Manager (SSM), with Kiln in a persistent remote tmux session. A phone-driven bot already able to execute commands on the Mac can use SSM to query and control the remote host too. The desired addition is live messages and safe terminal takeover on Ubuntu with the same safety and delivery semantics as macOS.

**Current boundary.** Ordinary Linux runtime support is best effort, as the root README states. Live control has a stronger restriction: `src/engine/engine.ts::runProcess` creates the live-input/checkpoint profile only on macOS with Claude Code 2.1.311, and `liveView` requires macOS for takeover capability. Ubuntu therefore does not merely lack test evidence; the current implementation deliberately leaves live messages and takeover unavailable. Tmux preserves the remote controller across terminal disconnects but does not enable those capabilities.

**Where a future change belongs.** Extend [Control a live Kiln session](../changes/kiln-live-session-control/kiln-live-session-control-prd.md) through a new change PRD, following its [technical design](../changes/kiln-live-session-control/kiln-live-session-control-technical-design.md). Preserve the existing [bot-control](../prds/kiln-bot-control/kiln-bot-control-prd.md) commands and their guarded, durable operation contracts. A future requirements session should determine any supersession pointers; this note changes no criterion.

**Candidate scope for that PRD.**

- Qualify a native Ubuntu/Claude version and authentication profile, initially Ubuntu 24.04, with accurate account/usage availability. A working ordinary Claude prompt does not establish live-input or checkpoint compatibility.
- Deliver literal live messages through Claude's supported input mechanism, retaining exact text, delivery receipts, retries and explicit uncertainty. Do not implement input by typing into or scraping a tmux pane.
- Establish safe checkpoints, finish or account for tools and descendants, release the exact owned provider conversation for manual terminal use, and preserve deliberate resume/verify hand-back. Never force-interrupt work or advertise safe release before ownership is established.
- Preserve existing execution/activity/session/attempt identity, command deduplication, stale-target refusal, unsent-message handling, audit continuation, completion checks and billing/delivery authority. Controller restart, input loss or an SSM disconnect must not duplicate work or imply delivery/release.
- Present supported/unavailable controls consistently in structured status, command responses and the browser. Enabling Linux requires native evidence; removing the platform check alone is not sufficient.

**Remote transport remains outside Kiln.** The bot should query each configured host separately, using the same OS user and state-root environment as its controller, and label results by host. Remote mutations use that host's PRD paths, status tokens and command receipts. A stopped or unreachable host must not become a successful empty inventory. A separate SSM command shell can run Kiln's CLI while the controller remains in tmux. The bot's host configuration owns instance/region/profile/user details. Multi-host discovery inside Kiln, a relay, SSH setup, public controller ports, credential management, automatic instance start and a background service are not implied by this idea. Browser access can use a separate authenticated tunnel.

**Native proof to plan.** Use disposable repositories and real Ubuntu provider/process/filesystem boundaries. Exercise literal input during text/tools/background work; safe checkpoint and descendant release; terminal discussion and return to the same conversation; stale/repeated commands; lost responses, controller restart and SSM disconnect/reconnect. Check both bot CLI and browser behavior and preserve existing ordinary pause/resume/verification. Include unsupported OS/version/profile cases proving a clear refusal with no provider input, takeover hold, new attempt or plan advancement.

**Interim refusal review, 2026-10-27.** Source tracing found existing guards already meet the bounded request to refuse unsupported live control without changing a run. `Engine.controlView` reports both controls unavailable. The live-message reason from `liveView` says “Live messages require the validated Claude Code 2.1.311/macOS profile.” Takeover says it is unavailable for the current Claude CLI/profile and points to end-of-activity pause. For a new instruction with the current status token and target, CLI commands reach `src/control/server.ts` and `CommandJournal.submit`, which returns `control_unavailable` (CLI exit 3 / HTTP 409) before applying a refused action; a refused message is recorded as not sent. With no eligible active target, the route refuses before admission. No runtime change was identified or delegated to current implementation chats. This was a source review, not a native Ubuntu live-command test; such native proof remains future work. The inspected Ubuntu workstation had no Kiln installation at that time.
