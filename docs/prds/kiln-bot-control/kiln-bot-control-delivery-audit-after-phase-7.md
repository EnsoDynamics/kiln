## Confirmed missing parts

### Independent account observations and public unknowns

`src/agents/metadata.ts::refreshClaudeForLaunch` awaits authentication, model refresh and enabled-skill reads together, then assigns identity `updatedAt`. `src/account/claude-account.ts::readAccount` similarly dates the earlier authentication after usage completion and does not preserve the final successful corroborating authentication's own date. Public `accountFacts.next_attempt` and the inspection cache carry these substituted dates. A controlled subprocess/readiness reproduction delayed only model refresh by 1,000 ms: authentication completed at `2026-10-28T02:42:58.256Z`, while identity was labelled `02:42:59.213Z`, 957 ms later. Preserve identity and usage as independently observed facts.

`parseUsage(..., false)` deliberately preserves the legacy no-plan/no-message policy. But absent/null usage rows then reach `AgentInfo.updateClaude` or the full-reader fallback in `refreshClaudeForLaunch`, which infers successful usage from no `limitsError` and assigns `limitsObservedAt`. `accountFacts` publishes `{ value: [], state: "current", reason: null }` although no usage report existed. Distinguish this from an explicitly reported empty array; correct observation metadata without turning optional usage or valid API authentication into a launch blocker.

`src/control/projection.ts::accountFacts` forwards `view.billing` unchanged. Standalone retained `account` has no encompassing controller/facts label, so cached billing is not marked last-known. Full status has an outer stale label but still omits independent billing availability/freshness. Browser `BillingPanel` separately supplies the connection-dependent labels; both providers' public account paths omit them. Cached `canLaunch/canApprove/canClear` may remain true as data; this is not evidence of an execution bypass. Preserve authority while distinguishing dated observations and unavailable facts.

The same projection forwards internal optional-field structures for usage and saved Codex provenance. Unreported percentages, reset times/durations and identity keys can be omitted, so neither serializer renders them explicitly unknown. The public contract requires null plus availability/reason. Normalize the public response without inventing provider values, changing storage/provider schemas or discarding independently known plan/route facts. A current observation with explicitly unknown identity is not, by itself, an invented account; broad anonymous-authentication or readiness changes are outside this gap. Keep Phase 7's completed Codex identity guard.

These paths are reachable through live `account`, `account --refresh`, full status and retained account/full-status reads. Actual-attempt versus next-account provenance, Claude same-account usage retention, Codex corroboration/dates and existing recovery/billing authority remain built and must be preserved.

### Inventory root failures

`src/control/private-state.ts::enumerateWork` returns error-free empty work whenever `existsSync(root)` is false. That result includes inaccessible ancestor traversal, not just a genuinely missing state root. The built reader returned `work: [], errors: []` for `/var/root/.local/state/kiln` while `lstatSync` returned `EACCES`; an independent built CLI call from unrelated cwd returned exit 0, `ok:true`, `inventory_complete:true` and zero counts. No privileged files were read or changed. The same enumeration also feeds targeted resolution. Preserve successful genuinely absent roots while exposing inaccessible/invalid roots as unavailable/incomplete.

### Frozen log content and failure contracts

`src/control/logs.ts::outputPage` repeatedly builds candidates with `result()`'s current collection time and measures `serialize(..., false)`. Text timestamps use variable-width local formatting. Identical frozen cursor/options can therefore select different content when collection time changes. A disposable 60,000-scalar saved entry, identical cursor and `--max-lines 1` produced fragments `[30016,45008)` and `[30017,45008)` at the two collection hours; both responses were exactly 16,384 bytes. JSON's fixed-width timestamp avoids this particular defect. The promised stable text must coexist with honest collection time and the complete byte cap.

The page's `previousNewline/prefixHash/readRecord` use shared `deadlineCheck`, which throws `state_unavailable`; the pinned `session.json` generation read also escapes as a generic failure when missing/corrupt/unreadable. Neither live nor retained error handling converts these to the specified `saved_output_unavailable`. Disposable expired-deadline and removed-generation probes returned `state_unavailable` in both cases. Preserve supported legacy generation handling, cursor binding, exact fragments, entry counts and explicit empty/history/input distinctions.

### Handoff ownership and absent inspection sidecars

`src/control/projection.ts::handoffProjection` captures `activeId` before awaiting Codex `initialize/thread/read/close`. Concurrent ordinary Resume can acquire that same saved conversation while the history read waits. The response uses the old active ID and can offer `resumable:true`, a manual command and `active_under_kiln:false`. The later Claude takeover-release check does not cover ordinary Codex ownership. Revalidate the selected conversation before offering instructions; this finding is a traced reachable race, not a claim that it occurred in production. Claude's synchronous transcript check, explicit retained selection and no-session paths were checked as siblings.

`cached()` treats absent `inspection-view.json` as normal. The retained `statusProjection` fallback drops the stopped-session selector/recovery facts and sets `human_requests:null` despite a readable saved Codex request. A disposable saved stop returned `ok:true`, no errors, complete history and `message_complete:true`, while omitting those required facts. Selected retained handoff can likewise return provider-available success with null continuation/fresh prompts and no explanation when instruction sidecars are missing. Preserve available authoritative facts and explicitly report unavailable ones; do not invent prompts or migrate records during a read. The no-cache path must not be presented as a complete stop/instruction result.

### Full-history resource and deadline bounds

`src/control/history.ts::readHistory` retains every full `SessionRecord` and additionally projects conversations/attempts. `statusProjection`, `result.ts::serialize`, server `c.json` and client `response.json` materialize the full result again. There is no bounded-memory spool/budget path as the design requires. Checks before synchronous `readFileSync/JSON.parse` and `runs.map` also cannot bound a single large final record, and no post-read check rejects its late successful result.

A disposable 30 MiB saved final message remained in the returned history. With an explicitly supplied 20 ms read deadline, the reader took 37 ms and returned `complete:true`, no errors. This demonstrates the missing post-read deadline check; it is not a five-second load-test result or a production memory measurement. The source trace establishes the unbounded materialization across both providers/live/retained paths. Preserve complete valid output, explicit incompleteness and pure reads while implementing the promised resource boundary.
