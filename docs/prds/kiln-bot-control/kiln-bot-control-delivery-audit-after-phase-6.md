## Confirmed gaps

### Codex account binding and failed-read availability — AC-SEE-03 and AC-ACCOUNT-01

`src/agents/codex-metadata.ts::readCodexMetadata`'s local `readAccount` reads account before → usage → account after. It then calls `codexAccount(after, usage, startedAt)`. That function combines the final email/plan with usage account ID/gauges and checks only optional final routing identity. `codexUsagePermission(before, usage, after)` checks account type and optional routing IDs, but never compares the before/after email or plan. Routing is optional in the supported `AccountResult` contract. An A → B switch during the read can therefore display A's usage as B's current usage and report positive recovery permission. `codexCredits` already rejects changed email/plan; that safeguard does not cover gauges or permission.

Missing executable, incompatible CLI version and outer RPC initialization/failure paths also leave the initialized, dated `{ agentId, startedAt, updatedAt, limits: [] }` account without `error` or `limitsError`; only readiness blockers change. `AgentInfo.refresh` publishes it. `accountFacts` uses the Codex `updatedAt` fallback and marks the null-identity object and empty usage array current rather than unavailable. The account-refresh route checks account/usage errors, not these blockers, and can return successful empty facts.

Both paths reach the public interface through `readCodexMetadata` → `AgentInfo.refresh` → `buildSnapshot.account` → `accountFacts` → live account/full-status routes and retained inspection cache. The permission also reaches existing `codexUsageRelease`; no later comparison restores the missing account corroboration. The finding establishes a reachable boundary defect, not a current production incident. Complete account binding/availability without adding account management, changing spending permission or weakening launch/recovery authority. Preserve the repaired Claude and actual-attempt paths.

### Complete command discovery and legacy-helper error meanings — AC-ACT-01

`src/control/help.ts::commandHelp` filters the root text inventory to `path.length === 1`; nested child listings run only for command/group help. Consequently `kiln --help` omits `audit status/snapshot/submit` and `delivery status/assess/prepare/evidence`, although the design explicitly requires the root command tree with those actual subcommands. Root JSON contains the contracts; the text renderer does not expose the full inventory.

`prompts/kiln-command-contracts.json` still gives `run` and `add-repository` only “Existing helper-specific errors; inspection stable error codes do not change this helper.” Their text and JSON references expose no actual error meanings. `runKilnCommand` distinguishes syntax/path/start-check/lock/port/schema failures; `runAddRepository` distinguishes outside/ambiguous workspace, stopped/unreachable controller and refused addition. Documenting those existing conditions and exits is required discoverability, not a change to legacy execution contracts. The five Phase 6 audit/delivery JSON-input contracts remain complete.
