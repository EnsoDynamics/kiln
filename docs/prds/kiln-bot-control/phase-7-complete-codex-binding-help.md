## Implementation and validation

Codex usage, ordinary-usage permission and optional credits now share one account-corroboration rule: both authentication reads must be ChatGPT, their email/plan must agree, a nonempty usage account ID is required, and every reported routing ID must match it. A stable known email can establish context when optional routing is absent; without email, both routing reads must identify the usage account. Changed or uncorroborated context yields unavailable gauges and unknown permission, without adding a launch blocker for optional usage.

Identity is dated when the final authentication read completes; gauges retain the usage response's own time; recovery permission is dated after corroboration. Unrelated model/skill/configuration completion no longer redates these facts. Retained Codex gauges carry their own source account ID through repeated optional failures, so an account ID from usage cannot be silently relabelled by a later routing ID. Same-account failures can retain original dated gauges as stale while fresh authentication and unknown recovery remain independently dated. Missing executable, incompatible version, initialization/RPC failure and account-read failure expose explicit account/usage errors. Initial failed or unidentified Codex facts are unavailable; previous successful identity/recovery can remain honestly stale. Legacy caches without independent usage/recovery dates cannot borrow authentication timestamps. Claude observation behavior and saved actual-attempt/original-attempt provenance remain intact.

Account-panel usage ages and stale notices now use the gauge observation independently of authentication, including when a later identity failure retains older gauges. Codex waiting/usage-stop views carry a separate allowance observation with date, state and reason. Both text consumers use that observation; pure retained full-status projection marks dated waiting/stop allowances stale and withholds undated legacy gauges without rewriting saved caches. Identity, usage and recovery authority remain separate.

Root text help now inventories every supported command, including all audit/delivery leaves. The `run` and `add-repository` references describe their actual positional syntax, cwd/value sources, setup/context rules, useful refusal meanings, execution formats and exits. Descriptive legacy error names are explicitly reference labels rather than new execution codes. The five completed audit/delivery JSON payload contracts are unchanged. No execution parser, provider sign-in, spending/delivery authority or command was added.
