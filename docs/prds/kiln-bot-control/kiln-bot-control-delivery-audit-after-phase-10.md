## Phase 10 repair and sibling confirmation

The [after-Phase-9 audit](kiln-bot-control-delivery-audit-after-phase-9.md) remains the historical non-clean assessment. Its output-open gap is closed by shared `logs.ts::openSavedOutput`: path/type checks precede opening; nonblocking/no-follow flags and descriptor type/ownership/permissions checks close the special-file replacement path. Both `outputPage` (including frozen cursors) and `recentSavedOutput` use it. Inventory, retained basic/full status and live status/logs therefore converge on bounded explicit unavailable/incomplete results. Regular-file text, fragments, snapshot identity and write-failure behavior remain reachable.

The receipt-selector gap is closed by command-status's required flag group and `parseCommand` enforcement before `targetWork` or controller/receipt lookup. Missing selectors return `invalid_input`; a caller explicitly supplying the valid literal ID `undefined` still uses ordinary lookup. Other required/exclusive groups and help's execution-requirement bypass remain intact. Main-agent source review confirmed these shared paths and the selection/error siblings, not only the happy paths.
