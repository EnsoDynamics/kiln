This audit does not grade tests or change implementation/tests.

`npm run build` passed from the isolated audit checkout. The freshly built CLI's `status --help --json`, `reply --help --json` and `reply --help` were invoked from unrelated `/private/tmp`, without a controller or provider request. Both serializers reproduce the contradictory availability/token wording and incomplete error inventories below. No full test suite was rerun for this document-only audit.

The actual Grok demonstration's retained command output, session attempts and durable receipts were independently read. The simultaneous inventory has one Claude controller working while Codex needs a reply. Literal reply delivery, terminal-history/no-message resume, stale refusal, retained unsent reply, acknowledgement-linked single advancement and unchanged six attempts on replay match the [release evidence](kiln-bot-control-validation.md#actual-grok-bot-caller-demonstration). The fixture's later audit-readiness stop is accurately disclosed; no active-pause claim is inferred from a pending pause.

## Confirmed gaps and conflict check

1. **AC-SEE-02:** `src/control/projection.ts::statusProjection`, especially the `lastActivity` expression and description, never consults the latest saved output/attempt or later pause/completion event when there is no current/wait/stop view. The main assessor confirmed the clearing paths in `src/engine/engine.ts` and conditional current projection in `src/engine/snapshot.ts`.
2. **AC-ACT-01 and AC-CLI-01:** `prompts/kiln-command-contracts.json:50–51` describes planned controls/null tokens; mutation limits beginning at line 513 say all changing forms are unavailable. The reference omits actual durable-control errors and `command-status` operation/effects/outcome fields. `src/control/help.ts::commandHelp` emits these entries directly in text and JSON. The main assessor reproduced this from the freshly built source.

History and requirements were checked for intentional changes and supersession. No later-built document changes these obligations. The unimplemented live-session-control PRD partially replaces other aspects of AC-ACT-01/02/03 only when built; it neither removes truthful help nor supersedes latest-activity reporting. Continue-added-phases does not replace these criteria. No deliberate alternative behavior was documented or found in the implementation history. These are ordinary omissions, not Changed outside the requirements. No new business assumption is needed.
