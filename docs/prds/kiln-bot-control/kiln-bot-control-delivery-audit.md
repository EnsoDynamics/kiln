## Confirmed gap and conflict check

**AC-SEE-05 — Recovery instructions without a saved conversation.** `src/control/projection.ts::handoffProjection` returns immediately when `chooseSession` finds no conversation, with only `resumable: false`, `reason: "No saved session."` and `session_id: null`. It never reads the available live/cached browser recovery instructions or returns their working directory. This is reachable: `src/engine/engine.ts::drive` can call `recordPlanStop` before creating the first session, and its first prelaunch readiness failure can record a selection stop. `src/engine/snapshot.ts::needsYouView` deliberately has no session for plan/selection stops and still returns `freshSessionCommand` and `freshSessionPrompt`. Status exposes those browser facts, but the dedicated `handoff` response drops them. The PRD's no-resumable-session branch and the technical design's handoff contract require preserving available fresh-session instructions. This is a missing error/recovery branch, not a new capability.

Explicit historical `--session-id` selection and the documented fallback to the latest saved conversation remain valid. This finding does not require changing those selection semantics; it concerns the early return when this execution has no saved conversation.

History and other governing requirements were checked for intentional changes and supersession. No later-built document changes AC-SEE-05. Live-session-control and continue-added-phases work does not replace this recovery-instruction obligation. No coherent intentional alternative was documented or found in the implementation history. The omission is a gap, not Changed outside the requirements. No new business assumption is needed.
