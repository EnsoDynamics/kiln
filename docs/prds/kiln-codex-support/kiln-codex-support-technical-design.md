# Technical Design: Codex support for Kiln

**PRD:** [Codex support for Kiln](kiln-codex-support-prd.md) · **Decisions:** [validated assumptions](kiln-codex-support-assumptions.md) · **Starting evidence:** [research](kiln-codex-support-research.md)

## Overview

Add Codex as a per-PRD agent through a narrow integration boundary within Kiln's existing local TypeScript application. Codex runs through its installed CLI's app-server over private stdio. The engine retains ownership of phase order, repository setup, checks, waits and recovery; each agent supplies its own readiness, metadata, conversation execution and audit evidence.

One PRD has one agent after Start. Each logical Kiln session has its own immutable agent and settings, and a separately recorded provider conversation ID. No new service, repository, database, scheduled job or desktop dependency is introduced. The published Enso Method skills are unchanged.

This design chooses the bounded raw-wrapper decoder and recorded-frontier candidate because normalized history demonstrably omits operations while recorded literal inputs show a feasible decoding path. First, prove unchanged published-method parent/child work and manual recovery against that candidate. Normal Codex execution integration, automatic phase passage and support claims remain blocked until this pre-integration proof passes. Skills stay unchanged; unknown evidence cannot be confirmed away or admitted by quietly broadening the grammar. Release acceptance additionally requires the available-Mac package and assembled-workflow evidence under AC-PROOF-03. Linux/Windows compatibility is best effort and explicitly untested under Doug’s 2026-10-23 PRD decision; native proof on those platforms is not a closure gate. Doug deferred actual usage exhaustion/recovery to its first live occurrence on 2026-10-23; pinned-contract and automated recovery evidence establish initial implementation acceptance, without claiming that real proof. A failed proof changes this design or raises its product consequence; it cannot quietly weaken the PRD.

**Current compatibility state:** [gate 1 passes for the corrected prerequisite candidate](kiln-codex-support-proof-results.md). The first grammar failed ordinary unchanged-method wrappers; the explicit bounded static-dataflow revision below now covers that unchanged work, same-conversation terminal recovery and real repository addition with a child. The complete audit detects exactly the deliberate outside marker. Verified uncommon request contracts passed real-pipe tests; no live provider request was observed. This qualified the pre-integration candidate; Phase 5 subsequently qualified the installed Mac workflow, including strict presentation comparisons and pure tool-catalogue queries described below. Full-history children can include copied parent metadata and unfinished parent starts. The first session metadata identifies the owning file; inherited-prefix records must exactly match the referenced ancestor records before attribution. Cross-check owning normalized turn IDs and raw terminal markers. Unresolved ownership remains inconclusive.

## Existing Code

**Posture: Preserve.** Existing Claude PRDs and historical output remain usable.

- Reuse phase planning, worktree setup, repository addition, Git/GitHub checks, instance locks, loopback API security, keep-awake and local storage.
- Extend settings, sessions, account views, output, workspace evidence and recovery at the agent boundary.
- Keep Claude's execution, transcripts and usage classification provider-specific; do not translate Codex into synthetic Claude events.
- Preserve existing PRD worktree paths, session IDs, waits, confirmations and recorded model facts during migration.
- Existing completion checks remain authoritative; successful model turns and progress displays never close a phase.
- Retain the existing confirmation/repair path for identified outside work. Missing Codex evidence remains a failed check, including after confirmation (AC-WORK-04).

## Architecture and Compatibility

### Agent boundary

The engine selects an installed agent adapter from the PRD/session record, never from a global default during recovery. The adapter contract has five responsibilities:

| Operation | Result and ownership |
|---|---|
| Inspect readiness | Executable/version, authentication mode, managed restrictions, required skills and supported unattended profile; typed blockers with remedies |
| Read catalogue/account | Dynamic model choices and independent account/usage readings; no inference turn |
| Start/resume/interrupt | Managed process controls, durable provider identity, normalized activity and terminal outcome |
| Read evidence | Complete or explicitly inconclusive conversation-tree evidence, independent of Kiln's captured output |
| Format recovery | Agent-specific sign-in, resume command and fresh-session guidance |

This boundary contains provider differences rather than redesigning the engine. Common output storage and Git-check input types are independent of either wire protocol. Every call returns a bounded success/error result; no provider failure selects another adapter.

Replaces in part: `docs/prds/kiln-v1/technical-design.md`, §Dependencies, §Design Decisions (agent execution and metadata); `docs/changes/kiln-multi-repo-delivery/technical-design.md`, §Sessions (agent-specific execution).

### Codex process and version contract

Use `codex app-server --listen stdio://` with Kiln's own child process, not the desktop or a shared daemon. `initialize` identifies Kiln and enables the experimental fields this integration requires, followed by `initialized`. Newline-delimited RPC requests are correlated by ID; server requests and notifications have separate handling. No network listener or external Codex host is enabled.

The validated macOS compatibility profile is **codex-cli 0.162.1**, proved through the installed two-phase actual-GitHub workflow in the shared proof results. Linux/Windows runtime remains explicitly untested. Shipping support for a version means its protocol fixtures and required real proofs pass. Initially accept only that version after its proof gates pass, not an unbounded minimum-version range. Broaden the documented compatible set after validating another version; unknown versions fail readiness with the version and supported choices. The compatibility profile includes raw history grammar and execution-tool configuration, not just RPC method names.

Require ChatGPT authentication and the OpenAI provider (AUTH-001). Do not read or copy authentication tokens, substitute API credentials, initiate login or modify the user's configuration. Account metadata may supply display identity and plan; credentials remain Codex's concern.

Metadata calls have a 30-second deadline including initialization; pagination has a per-call deadline and an overall bounded scan as specified below. Session turns have no arbitrary duration limit. Transport corruption, unexpected process exit and disconnected pipes end the attempt visibly; they never mean success. Failed persistence stops further turns. Existing platform process-tree controls supervise the app-server and its descendants.

### Selection and readiness

`kiln run` performs the common document/Git/GitHub checks before opening Documents found. It discovers agent executables without requiring either one, so a Codex-only installation reaches the chooser. A new PRD initially selects Claude Code; a missing initial Claude installation is a selection-specific readiness message with Start disabled, not a terminal startup failure.

Agent change before Start loads that agent's catalogue, account and readiness together. The selection generation is persisted and increases on agent changes, so restarting Kiln cannot make an older editor current again. Each asynchronous result carries agent ID and a selection generation; a result for an older selection cannot update the current snapshot. Clear the former agent's current account panel immediately. A refresh failure leaves an explicitly stale reading only for the same agent/account context.

Before Start and before every new conversation, validate the selected agent, current catalogue/choice, authentication, effective unattended permissions and enabled method skills. Inspect skills for the actual launch directory and repository contexts, including multi-repository workspaces; resolve plugin-qualified names to enabled entries and paths, not string aliases alone. Required engineering skills are `implement-from-requirements`, `deliverable-review`, `test-hardening`, `refactor-pass` and their installed method dependencies. A missing/disabled skill or a known incompatible hook/trust/organization requirement starts no implementation turn. After setup, repeat directory-dependent readiness against the assigned worktrees before the first turn; a failure preserves setup and selection at Needs you.

Do not relax an organization's restrictions. Codex readiness requires the configured profile to be permitted by `configRequirements/read`, effective thread-start settings and the compatibility proof. Unknown mandatory restrictions or known interactive hooks/trust requirements block with the terminal action required. Kiln never passes a hook-trust bypass flag.

## Models and Settings

A catalogue entry is `{ value, displayName, efforts: [{ value, label, description? }], defaultEffort?, selectable }`. Effort values are nonempty provider strings, not a shared five-value enum. Retain Codex's reported model names and effort descriptions. Follow every `model/list` cursor; exclude explicitly hidden/unselectable entries. A catalogue is discovery, not entitlement.

For the first Codex selection, choose the greatest numeric version of a selectable model matching the GPT Sol family (for example, `gpt-6.1-sol` sorts above `gpt-6-sol`), with `high` effort (UI-001). Do not choose Astra, Luna or an unrelated server default. If the catalogue cannot establish a unique latest Sol or does not support High, explain the conflict and require an explicit valid choice. Do not hard-code today's model ID as a fallback.

Before Start, switching agents restores that PRD's last choices for the selected agent. An invalid saved choice stays visible with its error. When an explicit model selection invalidates its effort, choose the model's advertised default effort and show the resulting saved pair and change explanation immediately; if the default is missing or invalid, require effort selection. The UI exposes only supported efforts and marks a model with no efforts as taking none.

An unavailable catalogue blocks a **new session**, not the running turn or the person's completion check. Reload the catalogue on selection, Kiln restart, account change and before starting a fresh conversation; a failed refresh is not replaced by fabricated choices. This validation applies where this PRD supersedes earlier permissive catalogue behavior, including new Claude sessions; migration preserves their stored choices. A resumed conversation is validated against its recorded pair, never next-session settings. An access refusal is Needs you with the provider's error, never substitution.

Agent becomes fixed in the atomic Start record before setup; if setup fails, it remains fixed while any repository setup persists, and otherwise can be changed on Documents found. Once implementation starts, it stays fixed permanently. Settings can change model/effort for future sessions while work runs or is paused, but never rewrite any session's pair.

For Codex, request the exact model and effort and set `allowProviderModelFallback: false` on creation. Compare thread-start/resume effective settings before sending work. Save per-turn execution model/effort from the versioned persisted `turn_context`, not `Thread.model`/`reasoningEffort`, which describe mutable configuration rather than per-turn execution. Keep requested, effective configuration and observed execution facts distinct; disagreement or missing required provenance is visible at Needs you. Later metadata refreshes never rewrite the original account or execution facts. Manual turns may have different settings; retain them as separate observed attempts, and a Kiln resume explicitly restores the original recorded pair or reports refusal.

Replaces in part: `docs/prds/kiln-v1/technical-design.md`, §Account and Usage (models/effort), §Snapshot (settings and each phase's model), §Where a Feature Stands: what `kiln run` does — Startup order, and §Testing Approach — Models and effort (new Claude sessions also require a confirmed catalogue choice instead of launching an unchecked saved alias).

## Codex Authority and Conversation Lifecycle

### Unattended execution profile

The proposed Codex profile is `approvalPolicy: on-request`, `approvalsReviewer: auto_review`, workspace-write sandbox, and network access for authorized dependency/test/Git operations. The filesystem grant includes the workspace folder plus a one-repository worktree located outside that folder. A folder added inside the existing workspace root does not require expanding authority to sibling main checkouts.

Native Windows uses **explicit MXC**, with process-local `windows.sandbox=mxc`, without fallback or persistent configuration changes. Before work, require `windowsSandbox/readiness` with null params to return `ready`, compatible managed requirements and the expected effective workspace-write/on-request/auto-review settings. From the assigned launch directory, run the documented no-model-turn startup check `codex -c windows.sandbox=mxc sandbox --include-managed-config --permission-profile :workspace -- cmd.exe /d /c echo MXC_OK`, bounded by the 30-second metadata deadline; require `MXC_OK` and exit code zero. `notConfigured`, `updateRequired`, unsupported MXC, or a failed startup check blocks the selected agent with the required terminal/device action. This command checks sandbox startup, not enforcement of every assigned root; native Windows execution and root enforcement remain untested, outside this delivery’s acceptance gate. Kiln never invokes sandbox provisioning, changes execution policy, relaxes managed constraints, or substitutes legacy sandbox modes.

Git metadata of a linked worktree can lie outside the workspace and remains protected. The session requests reviewed escalation for authorized Git operations; Kiln does not grant the whole source checkout or common Git directory as writable simply to make Git succeed. The launch prompt states the assigned branches/paths and commit/push authorization, and distinguishes a sandbox restriction from an automatic-review denial. A denial remains effective and visible. Only the session performs Git delivery.

Keep the supported code-mode host enabled. Audit its recorded wrapper programs through the bounded decoder below; do not disable tools to simplify auditing. The compatibility profile requires enough persisted raw input to decode relevant operations without executing provider-supplied code. If ordinary method work cannot produce complete evidence under that profile, the version cannot be advertised as supported. An optional executed-tool metadata flag is not a completeness guarantee.

Preserve each repository's instructions explicitly: prompts require reading its `AGENTS.md` and `CLAUDE.md` before changing it, including repositories added through Kiln. Codex's `instructionSources` records the files loaded automatically; it is not evidence that every sibling's instructions loaded. Do not merge project configurations or overwrite provider instructions. Display the selected agent's actual project-settings limitations on Documents found.

Every server request is handled promptly and saved with the decision:

| Request | Kiln response |
|---|---|
| Command/file approval reaching the client | `decline`; retain request and outcome in output. Automatic review is Codex's responsibility, never blanket acceptance by Kiln |
| Permission expansion reaching the client | Empty granted permissions, turn scope; no new grant |
| MCP elicitation | `decline`, no content |
| User question, including connected-tool consent | Interrupt the turn and stop at Needs you with the full request; never fabricate an answer |
| Unknown server request | Unsupported-request RPC error, interrupt and stop with method/request visible |
| Async question embedded in an agent message | Detect structured `questions`, interrupt and stop with the question |

Kiln sends no `acceptForSession`, policy amendment, purchase/reset-credit request or bypass flag. A request handler must settle or initiate interruption within 5 seconds. A blocked human request is a recorded stop, not an invisible pending promise. Parent and child requests receive the same policy. Existing checks still run after the attempt; their pass may finish the work before any retry/recovery decision.

### Identity before work

Allocate a local Kiln session ID and persist its launch intent with agent, requested model/effort, working directory, assigned repositories and account reading before spawning. Start the app-server and record PID/start time immediately. `thread/start` creates a persistent conversation; save returned `thread.id` and effective settings atomically **before `turn/start`**. Codex's `thread.id` is the resume ID; its `sessionId` is the wider tree's identity and is stored separately.

The prompt and any skill input reference the discovered installed skill path without modifying its content. Launch and resume use the existing phase/PR templates with agent-specific nouns and invocation syntax; resume note remains first, outside-workspace instructions next, carry-on instruction last. Never replace `baseInstructions` merely to invoke a skill.

Persist a launch-attempt intent before sending `turn/start`, then returned turn ID and observed settings when available. A newly created thread is not materialized until its first user input: its first dispatch has an empty prior-turn frontier without calling `thread/turns/list`; resumed conversations exhaust that history before dispatch. A crash before `turn/start` cannot have performed work; an orphan empty thread is not adopted by guessing its title. A crash after dispatch uses the saved thread ID and authoritative history to determine whether the turn started. Do not resend a possibly delivered prompt automatically. If history cannot settle that ambiguity, Needs you preserves the conversation and work. Reconcile never launches two turns for the same session.

A normal session ends at its parent turn's terminal state, after tracked child turns have settled. Before closing the private server, page `thread/loaded/list` and intersect it with the parent and known descendant identities; never resume cold historical children for cleanup. Page their `thread/backgroundTerminals/list`, persist reported process handles and live OS PID/start identities, call `thread/backgroundTerminals/clean`, then verify no registered terminals remain. Bound the whole provider cleanup to 10 seconds. Whether it succeeds or fails, close the server and perform identity-checked OS termination of the tracked processes. Record semantic turn outcome separately from process exit. A long-lived server exiting zero is not a completed phase. Final text is the current attempt's `agentMessage` with final phase; failures and raw stderr remain accessible when no final text exists.

### Resume and stopping

Before every resume, stop any still-owned process using PID plus start-time verification, run the existing completion/workspace checks, and refresh account metadata. A passing completion check finishes the work without resuming. Automatic interruption/usage recovery requires a passing workspace check; failed or incomplete evidence goes to Needs you. Explicit manual Resume remains available when Codex can resume the saved conversation, including while outside work is unconfirmed or the workspace audit is inconclusive. It sends the person's note and the identified outside-work repair instructions before the carry-on instruction. An inconclusive audit also names the evidence that must be recovered or made readable; resuming, confirming repairs or starting another session does not erase that obligation or make it pass.

`thread/resume` uses the saved thread ID, original directory, model/effort and current assigned workspace policy. Send no caller-supplied replacement history and do not fork the conversation. An effective setting mismatch blocks before a new work turn. Missing/unresumable conversation removes resume actions and retains the existing fresh-session prompt; the prompt never substitutes for missing evidence in an earlier session.

The copyable terminal command changes to the saved working directory and invokes `codex resume <thread.id> --model <recorded model> -c model_reasoning_effort='<recorded effort>'`. Use the platform's argument quoting; omit effort when absent. The terminal retains Codex's interactive permission controls. Manual work is reread from the same original conversation tree; it is never inferred solely from Kiln's logs. Sign-in guidance uses `codex login` in a terminal and existing ChatGPT authentication.

On Ctrl+C/SIGHUP/SIGTERM, record interruption first, request `turn/interrupt` for the parent and tracked live child turns, and wait for terminal state. Then perform provider terminal cleanup and close stdin. Terminate the owned process groups and remembered live PID/start identities, with bounded grace and escalation; a second Ctrl+C shortens the turn grace. Never roll back edits. After stop begins, save arriving evidence but perform no verdict or next-session launch until reconciliation.

Retain existing sleep and restart rules. Codex model activity comes from genuine agent-response items, not tool completion, error notifications or synthetic status messages. On wake refresh account/usage and inspect persisted/runtime turn state before deciding an interrupted conversation needs resuming. The 2026-10-23 real proof found that a detached child with a replacement environment can outlive `turn/interrupt`, ancestry polling and an inherited marker on macOS. Doug subsequently approved the limited native contract in RECOVER-001: strengthen native cleanup and disclose independently detached programs, without privileged helpers or an isolated architecture. Preserve that counterexample as a limitation characterization, including separate driver cleanup; do not call it a containment pass.

Persist `cleanup: tracked_processes_stopped` only when provider inventory/cleanup and the tracked OS process checks succeed. A failed cleanup or unavailable provider inventory after initialization produces `unknown` with its failure retained. On crash reconciliation, successful identity-checked termination establishes only the saved/rediscovered tracked set; the same limitation warning remains. Never use `complete` to imply universal containment. Save `cleanupWarning` and expose it through the runner's separate `onWarning` callback, without fabricating provider events or contaminating raw stderr. Workflow integration shows guidance where the terminal describes Ctrl+C and in the browser recovery view: independently detached programs may keep running; check background servers or jobs before resuming. Actual cleanup failures prohibit automatic continuation and remain visible until the known process problem is resolved. Platform proofs verify this bounded contract; PID ownership never authorizes ending an unrelated terminal session. Normal execution stays gated until 3b2's complete workflow integration is proved.

## Workspace Evidence, Output and Progress

### Authoritative evidence

For every recorded session of the phase, read the provider's own history, including terminal resumes and all descendants. Kiln's event capture is supplementary evidence and the source of live output, never the sole workspace audit. A turn that was dispatched counts as possibly having acted even when no successful initialization/model response was recorded.

For Codex, use metadata and paginated history to discover the tree: `thread/read`, `thread/turns/list` with `itemsView: full`, `thread/items/list` when supported, plus `thread/list` filtered by `ancestorThreadId`, with explicit subagent source kinds and separate archived/unarchived passes. Exhaust every cursor. Union descendants from returned parent links, collab receiver IDs, subagent-activity IDs and the persisted spawn records; recursively verify referenced children. A page of summaries, an empty default interactive listing or a parent's final report is never complete evidence.

The audit reads both normalized history and the local persisted rollout returned by `thread.path`, resolving within the initialized Codex home, because normalized history does not guarantee complete raw tool inputs. This is an unstable provider field: support is pinned to the validated raw grammar. Use the returned path rather than reconstructing Claude-style paths. Re-discover on every audit because archival can move it; if necessary locate only that recorded thread ID under Codex's sessions/archived_sessions and verify session metadata matches. Never scan unrelated conversation contents. Do not open Codex's database directly.

The evidence reader inventories every persisted function/custom-tool invocation and its outcome before interpreting safe normalized commands/file changes. Preserve raw inputs, result status, originating thread/turn/call ID, timestamp and working directory/turn context. Track known direct shell and patch calls, edits/moves/deletes, delegated work, commands that failed after partial effects, and calls interrupted without a result. Unknown executable wrappers or tool forms that might conceal relevant writes produce an **inconclusive** audit fact; do not evaluate arbitrary JavaScript to extract actions. Native command events cannot cover a missing raw invocation by assumption. Decoding a recorded call proves its input was visible, not that the called command succeeded.

For a code-mode `exec` wrapper, parse its JavaScript into an AST using a non-executing parser. The revised candidate uses bounded static dataflow over literal data: `await`, exact tool names, blocks, immutable declarations/destructuring, string concatenation/templates, arrays/objects/spreads, literal-data property/index reads, and known `Promise.all`/`allSettled` and output helpers. It admits `for...of`, array `map`/`forEach` callbacks and canonical zero-based counted loops only over statically known finite arrays. Callback bodies must themselves satisfy this same grammar; they are traversed as syntax, never invoked as JavaScript. Phase 3b2's native run additionally required `results.forEach(text)`: exact reserved presentation globals (`text`, `notify`, `image`, `audio`, `generatedImage`) are permitted as callbacks over those same finite arrays. They cannot dispatch work, cannot be shadowed, and their opaque outputs cannot become tool inputs; arbitrary identifier or member callbacks remain unsupported. The [workflow results](kiln-codex-support-workflow-results.md) record qualification evidence and the initial refusal. Strict equality/inequality (`===` and `!==`) may compare statically known primitive values; an opaque result, pending promise or nonliteral operand makes the comparison unknown. This admits ordinary output-only status checks over settled results without reading tool outputs. Both operands and both conditional branches are always inventoried, so comparison cannot hide a tool call or derive a tool input from an opaque result. Object identity, loose/coercing equality and other binary operations remain unsupported. The reserved `ALL_TOOLS` catalogue is metadata, never an executable tool reference. A directly rooted display query may use pure `filter`/`map` expression callbacks, descriptor `name`/`description` string fields, string concatenation, literal regular-expression `test`, plain literal objects and bounded literal `slice` arguments. Validate every callback as syntax without evaluating the catalogue or invoking it. Calls, assignments, computed access, callback blocks and arbitrary helpers outside that pure grammar are inconclusive; the query result is always opaque and cannot become a tool input, callback/dispatch target or loop bound. Only the counted index may advance; source assignments, mutation and arbitrary helpers remain unsupported. Bound each array/iteration to 1,024 elements, the program to 1 MiB and traversal to 50,000 steps; exceeding a bound is inconclusive.

Tool returns remain opaque tainted values. Their fields and spreads may flow to display helpers, but never to a tool input or a loop bound; Promise aggregation preserves only its statically known array length. Known pure string predicates may fold literal conditions; otherwise traverse all branches conservatively, and unresolved values cannot determine tool arguments. Every complete tool input must derive solely from literal immutable data. Reject dynamic code generation, arbitrary callbacks/helpers, computed tool names, aliasing or mutation of tool references, undecodable inputs and malformed syntax. Never run recorded JavaScript or inspect actual tool output to guess an input. A complete, untruncated structured executed-call list can supply inputs only when the validated provider contract proves coverage; absent/incomplete metadata never replaces decoding.

The decoder returns `{ callId, operations[], coverage: complete | inconclusive, reason? }`, not a success judgment. Every raw wrapper must have complete coverage before the session audit can pass. This introduces a small runtime JavaScript-parser dependency; the compatibility grammar and verified raw fixtures own its behavior, not a broad JavaScript evaluator. Normal published-skill work must pass real proof with this grammar; implementation must not quietly broaden it or teach the model a new skill-specific syntax to hide a failure.

Normalize supported decoded operations into the existing workspace-check policy: file writes and mutating Git operations placed by their actual working directory and explicit path/branch arguments. Reuse its definition of outside checkouts, `.agent-sessions` exemption, realpath comparison and confirmation/repair flow. Select the shell reader from recorded executable/argv when present. The pinned local exec tool also records its default shell in authoritative `world_state.state.environments`; this selects the reader for default-shell calls whose native events are omitted, using the verified version-specific exec tool contract and recorded literal command/cwd. Never infer that default from Kiln's host environment or an adjacent call. An explicit shell override requires matching recorded executable/argv. Unwrap a recognized POSIX `-c`/`-lc` body before using the existing shell interpretation limits. Missing recorded shell identity, changed/unrecognized tool parameters or an unsupported invocation is inconclusive. File renames cover both endpoints; failed/partial operations count when effects cannot be ruled out.

**Native PowerShell reader.** Pin the actual PowerShell executable/version in the Windows compatibility profile. The qualified parser implementation currently requires `pwsh` 7.5.2, as exercised on macOS; this establishes parser behavior, not a native Windows execution profile. The native launch profile must still check its actual executable/version before permitting work; Windows runtime validation is unavailable for this delivery and must not be claimed from the macOS parser evidence. Admit recorded `powershell.exe`/`pwsh.exe` invocations with `-NoLogo -NoProfile -NonInteractive -Command` and a fully recorded body; equivalent provider launch forms require verified fixtures before admission. Parse that body through a fixed Kiln helper invoking `System.Management.Automation.Language.Parser.ParseInput`. The helper receives evidence only as stdin data and returns AST/tokens/parse errors; it never evaluates evidence, loads its profiles, invokes its script blocks or passes an execution-policy bypass. Its bounded process and input/output share the audit deadline. Parser absence, failure or unsupported syntax is inconclusive.

Admit literal command names/arguments, quoted literals/here-strings, constant local assignments, statement lists and pipelines. Track literal `Set-Location`/`cd`, `Push-Location`/`pushd`, `Pop-Location`/`popd`, Git directory options and explicit literal `GIT_DIR`/`GIT_WORK_TREE`. Direct `git`/`git.exe` or an identified Git executable uses existing Git mutability rules. Conservatively inspect all branches; unresolved directory state cannot place a later mutation. Changed aliases/functions, dynamic command names, splatting, `Invoke-Expression`, dot-sourcing, encoded commands, `-File`, unresolved relevant arguments and unsupported nested shells are inconclusive. Ordinary non-Git external programs retain the existing policy's limits on claims about arbitrary subprocess effects.

| Recognized literal PowerShell write | Recorded mutation |
|---|---|
| `Set-Content`, `Add-Content` with `-LiteralPath`; `Out-File` with `-FilePath`; `>`/`>>` to a literal file | Destination path |
| `New-Item -ItemType File` or `Directory`, with literal `-Path` and optional literal `-Name` | Created path |
| `Copy-Item`/`Move-Item` with literal `-LiteralPath` and `-Destination` | Copy destination; both move endpoints |
| `Remove-Item -LiteralPath` | Removed path |

Admit only these path forms and known non-path options; wildcard/provider paths, unsupported write cmdlets/options and unresolved destinations are inconclusive. The fixed parser helper reports its clean runtime alias inventory without executing evidence. Reject aliases except the explicitly supported location aliases, module-qualified cmdlets, unknown cmdlet forms, nested-shell basenames (bare or rooted), and variable-mutating common parameters including their accepted prefixes/aliases; these must not fall through as ordinary external programs. For directory destinations, conservatively cover both the named destination and destination/source-basename rather than guessing whether a container existed. Resolve relative paths from recorded cwd/location and native drive-absolute or UNC paths; reject drive-relative `C:foo`, unknown PSDrives/providers and uncaptured variable/home expansion. Reuse physical nearest-ancestor resolution for junctions, Windows separator-boundary/case comparison and the existing exemption. Unreadable or ambiguous path identity is inconclusive. These rules interpret recorded operations; they do not execute PowerShell to discover what a command would do.

A failed/unavailable raw file, unexhausted cursor, missing child, unknown action grammar, corrupt record or a live/unsettled parent or descendant fails Stayed in the workspace. Check tree membership, available runtime activity and raw-source identity/frontiers before and after the scan. A changed tree, new turn, replacement/truncation or changed source frontier makes that scan inconclusive; retry within the same total deadline or return the failure. Establish the recorded turn frontier from raw `task_started`/`task_complete` events, or the verified 0.162.1 `turn_aborted` event with reason `interrupted`, matched by `turn_id`; an abort settles only a matching normalized interrupted turn, cross-checked against normalized `Turn.status` (`completed`, `interrupted`, `failed`, `inProgress`). An unmatched start or in-progress turn remains inconclusive until authoritative terminal evidence settles that same turn. Runtime idle/notLoaded status or absence from a loaded-thread list is supplementary, never proof that an externally reopened conversation stopped. Stable before/after raw/tree frontiers establish this check's coverage; a global exclusive session lease is not required and the result makes no claim about future work. Known interrupted attempts can be audited conservatively once their terminal state and owned-process cleanup are established; an absent tool result never proves no effect.

A truncated final JSON record is incomplete evidence until complete provider evidence repairs the gap; a person cannot confirm unknown Codex evidence into a pass. It is not silently skipped. Confirmations cover only identified outside-workspace changes at the exact evidence frontier evaluated at that stop (thread IDs, last observed raw positions/turns and last-modified facts), not every future event bearing an old timestamp. New manual work or a newly discovered child invalidates the old coverage. Preserve existing Claude confirmation semantics for migrated Claude sessions.

Evidence is a policy check over recorded tools, not an operating-system proof that arbitrary shell programs cannot write elsewhere. The sandbox and automatic review remain separate safeguards. Missing recorded Codex evidence never becomes a passing check; existing Claude confirmation semantics remain unchanged. Repeated inability to produce an auditable normal Codex session is a compatibility blocker, not a reason to require the person to confirm every phase.

Stream audit scans with 100-record pages, at most 4 concurrent provider reads and a 2-minute total deadline. On a deadline, return a visible inconclusive check; retrying Check again performs a new complete scan, never blesses a partial scan. Bound memory by streaming raw files and pages with owner-only temporary disk indexes, rather than loading entire histories. Enforce explicit fail-closed limits of 16 MiB per raw/transport record, 4,096 threads, 100,000 cursors and 200 distinct findings/problems. A common phase-check deadline covers all its sessions; exceeding any limit is inconclusive. Persist a compact per-check frontier/findings, not another mutable copy of provider history. Do not delete provider history or Kiln output automatically.

## Account Usage and Recovery

### Readings and identity

Call `account/read` and `account/rateLimits/read` without a model turn. Use a freshly started bounded metadata process when refreshing to observe terminal login changes; never assume a session server's cached credentials reflect them. Each snapshot carries agent, reading start/finish times, known account identity, field-level unknowns and errors. Keep a last successful reading only with its original timestamp and stale indication. A fresh session records the account before work; each resume attempt records its own account without rewriting the session's original account.

Prefer `rateLimitsByLimitId`; use the legacy single-bucket payload only when the map is absent and identify it explicitly. Flatten every reported bucket/window into a collection keyed by reported limit ID plus window role. Store reported label/ID, duration, percent used, reset time and available model scope. Primary/secondary are identifiers, not names for fixed durations. Missing windows/percent/reset/account fields remain unknown, including an empty map. Warn at 80% for known percentages. Do not show credit balances as usage percentages or assume paid credits authorize automatic spending.

The usage identity is the nonempty `account/rateLimits/read.result.accountId`; `account/read.result.account` has no account ID. Bracket each recovery usage read with fresh `account/read` calls. Every supplied `result.workspaceRouting.chatgptAccountId` must agree with the usage identity; absent optional routing metadata alone does not invalidate the backend's account-validated usage response. A changed authentication mode, conflicting supplied identity or missing usage identity makes recovery evidence unknown; email/plan cannot substitute. A fresh metadata process observes the current terminal authentication. `normalModelSlug` describes a quota alias's display/reasoning relation, never the refusing allowance's scope.

Refresh at least every five minutes while Kiln runs, on selection, before starts/resumes, immediately after a confirmed refusal, on wake and at the applicable reported reset. Join duplicate reads but a read begun before the refusal cannot release its wait. Provider notifications can refresh display sooner; partial notifications do not clear prior unknown or administrative fields. Revalidate through a full read before automatic recovery. Lookup failure alone does not block permitted normal work.

### Classification and bounded release

A confirmed Codex usage stop requires a structured terminal `usageLimitExceeded` provider error for that attempt, with no subsequent successful model activity in that attempt. `rateLimitExceeded`, HTTP 429 alone, network errors, retry notifications, prose and old failures are not usage stops. Preserve `willRetry`; do not classify an intermediate error while Codex is still retrying. Administrative/spend-control failures remain distinct even if accompanied by quota information.

First run completion checks. A pass finishes; failed workspace evidence stops at Needs you; otherwise apply the PRD recovery table. A readable applicable allowance permits waiting while blocked, but unknown percentages or missing permission never establish a healthy or released state. Keep the existing manual Resume now, pause, keep-awake and wait lifecycle. The applicability/release result is one of `allowed`, `blocked`, `unknown`, with evidence and account scope, not a boolean derived from a percentage.

`account/rateLimits/read.result.ordinaryUsageAllowed` is **account-wide ordinary included-usage permission**, not model entitlement or a particular window's recovery. `false` blocks; null/missing is unknown. A fresh full `true` with a known usage identity and consistent available routing corroboration permits **one attempt** to resume the original conversation with its original settings, absent known applicable model, administrative or spend-control blocks. It does not guarantee inference access. Never derive permission from percentages, reset times, credit balances, purchase offers or earned reset credits; `normalModelSlug` cannot establish which window refused. Known other-model blocks do not stop the original model when their scope is explicitly established.

In 0.162.1, the recognized `TurnError.codexErrorInfo` value is scalar `usageLimitExceeded`; it carries no structured model, allowance or reset. This profile therefore cannot use reset-only recovery: unknown ordinary permission goes to Needs you/manual recovery. Never scrape `message`/`additionalDetails` or attach a convenient window reset to the refusal. AC-RECOVER-03's conditional reset-only rule applies only to a future validated profile with an applicable structured reset; no speculative field or timer is implemented for this candidate.

Persist a consumed semantic evidence fingerprint before dispatch, across restarts. The first fresh positive reading after a refusal can permit one attempt even if pre-refusal permission was also true. A repeat refusal before meaningful model activity suppresses another attempt on unchanged true readings. Release then requires a proven blocked-to-allowed transition, a different stable account with fresh positive permission, or another newly established applicable recovery event supported by the validated profile. Timestamps, request IDs, unchanged percentages and repeated true readings are not changes. Unknown identity or scope cannot bypass suppression. Recreate/resume the private server under current authentication and record each attempt's account; changed email alone cannot release a wait. Existing Resume/Check again locking serializes these decisions.

Replaces in part: `docs/prds/kiln-v1/technical-design.md`, §Account and Usage; `docs/changes/kiln-usage-limit-recovery/technical-design.md`, §Design Decisions, §Recognizing a Usage Limit, §The Wait, §Snapshot (Codex classification, readings and bounded recovery; Claude classifier/release rules otherwise retained).
