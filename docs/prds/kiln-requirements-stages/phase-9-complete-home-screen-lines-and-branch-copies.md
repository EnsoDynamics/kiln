**Phase plan:** [Execution order](kiln-requirements-stages-phase-plan.md)
**Model tier:** standard

## Summary
Fix the home-screen and start-check gaps the delivery audit found:
- Each Under way line says the stage the PRD reached: a Kiln run between stages, and a PRD whose refinement or feedback round is part-way through.
- A PRD that changes other repositories names only the others, each once.
- Material whose intake record isn't on the shared branch is Not ready yet, with the commit step, and `kiln run` names that step too.
- A PRD held only by origin's copy of a branch is listed and opened from that copy.
- The home screen gives the reason the current plan read failed.

## What the audit found missing
- **AC-HOME-04:** `recordLine` (`src/home/scan.ts` ~line 109) gives a Kiln run's Under way line as a bare "Requirements." in several cases: between stages (every finished stage has `pushedSha`, so `findLast(!pushedSha)` finds nothing, as when the run is paused between stages), before the first stage session, while a feedback session runs (no `expected`, empty `ran`), and while the standing is unknown (`kiln:next`). The record already holds the stage reached: the last finished stage, `standing.next`, or `standsAt`.
- **AC-HOME-04:** a PRD placed Under way only by `{folder}-prd-refinement-state.md`, `{folder}-design-refinement-state.md` or `{folder}-pending-feedback-changes.md` (`inProgress`, `scanRepository` ~line 377) gets a line built from `documentsStand` alone (~lines 391–396). An example is "Started by hand. PRD written, no technical design yet. Kiln continues from there…". The file says which round is part-way through, and the line never names it. When the file is uncommitted, `kiln run` refuses the start (`partWayProblems`), yet the line says Kiln continues from there. **AC-BEGIN-04** shows where the PRD stands "as the home screen does" through the same `documentsStand` (`adoptStartedByHand`, `src/kiln-command.ts`). So the screen before Start must name the round as well, for a committed design-refinement state or pending-feedback file that `kiln run` accepts.
- **AC-HOME-10:** `scanRepository` (`src/home/scan.ts` ~lines 374 and 384) builds `alsoChanges` from `namedRepositories(plan.phases, name)`, which drops a name only when it equals the main checkout's folder name. The method's phase documents name repositories by address path (`<owner>/<repository>`), which `readRepositoryName` accepts. As a result, the PRD's own repository is listed among "the others it changes". On a started run, one repository can appear twice, once as its recorded folder name and once by its address path. Map each written name to Kiln's name for it before dropping the PRD's own and merging, as the engine does with `recordedName` (`src/engine/plan-repositories.ts`; engine.ts ~line 11437). With no record, compare against the repository's own `origin` address path. The Not ready yet line for a PRD in a repository with no known shared branch (the `!shared && !started` branch, ~line 360) is also affected: it runs `continue` before the phase documents are read, so it names none of the other repositories.
- **AC-HOME-02, AC-HOME-03, AC-HOME-13 (row 2), AC-BEGIN-03:** a source folder with a brief and `received/` committed on the shared branch, and its intake record only in a worktree, on another branch or on origin's copy, is listed under Ready to start. `scanRepository`'s `intakeAnywhere` (`src/home/scan.ts` ~line 215) counts the intake record from any copy and so skips the `received/` row. Its Review and start then fails, because `inspectSource` (`src/requirements/source.ts` ~line 189) looks for the record only at the local shared commit. Both places must judge the intake record on the shared branch's copy. The line must be Not ready yet with the one step left: commit the intake record on the shared branch, or bring the local shared branch up to date when only origin's copy holds it. The same case also makes `kiln run` answer "Write …-requirements-intake.md: … has no intake record yet." for a record that is written but not committed there. That message must name the commit or bring-up-to-date step, through `notCommitted` and `elsewhere`, as the brief's message does.
- **AC-HOME-13, AC-HOME-04, AC-BEGIN-08:** `holdingByDirectory` (`src/requirements/branches.ts` ~line 149) and `branchesHolding` (~line 63) record `copies[0]`, the local copy of a branch name. They do so even when only origin's copy holds the directory. Take a stale local `prd/x` with the PRD pushed from another computer. `scanRepository` lists files at the local tip, finds no `{folder}-prd.md` and lists the PRD nowhere (~lines 352–356). Its source material is hidden by row 1 too, and `kiln run` reads the local tip. Record the copy that holds the directory: the local one when it holds it, otherwise origin's. Update the design's sentence "the copy read is the local one when it exists, otherwise origin's" (§What `kiln run` accepts) to match.
- **AC-PLAN-05:** the home screen's failed-read line comes from `planFailure` (`src/home/home.ts` ~line 321). That returns the first failure saved under any agent and fingerprint, not the failure of the read that just failed. After a failed read of an earlier method, the line names the older reason. Give the reason saved for the agent and fingerprint `readPlanForHome` read, for example by having it return that reason.
