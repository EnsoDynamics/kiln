# Kiln multi-repo proof run results

Results of the proof runs for [Kiln multi-repo delivery](../changes/kiln-multi-repo-delivery/kiln-multi-repo-delivery-prd.md) (AC-PROOF-01), done in [Phase 3](../changes/kiln-multi-repo-delivery/phase-3-proof-across-repositories.md). Unlike v1's rehearsal, nothing is stood in for: the built `kiln run` from `develop`, the real Claude Code, and four real private GitHub repositories made for this proof, checked out side by side in `~/devel/kiln-proof/`. Their pull requests are the evidence and are never merged.

| Repository | Role |
|---|---|

The proof features are in [`scripts/proof-run/greeting-card/`](../../scripts/proof-run/greeting-card/) and [`scripts/proof-run/slugify/`](../../scripts/proof-run/slugify/), seeded by [`seed-multi-repo-proof.mjs`](../../scripts/proof-run/seed-multi-repo-proof.mjs). **How the outside edit was made.** The edit came from a turn the person added and asked for, not from a Kiln-launched turn, and the phase was already at Needs you (for Pushed) when Check again found it. Kiln's own sessions are told to stay in the workspace and did, so an outside edit had to be asked for, as v1's proof had to break the push URL to get a stop. It counts as the session's edit: it is the same session ID and the same transcript, which is all Kiln reads; AC-OUTSIDE-03 names "one the session makes once resumed"; and the technical design's Testing Approach lists "a turn added by a manual `claude --resume`". A Kiln-launched turn's own edit outside the workspace was not seen on a real session; the unit tests over recorded transcripts cover it.

Also seen:

- **The transcript reader on full sessions.** Seven sessions' transcripts were judged: four phase sessions, two of them with a person's resume turn added, and three pull-request sessions. None failed Stayed in the workspace, and the one file-tool write outside it was caught. What they exercised is narrow: the Kiln-launched turns used only Bash (45 calls, including `git` inside worktrees and `kiln add-repository`) and Read (3); none used Write or Edit, none started a subagent, and none ran Git in an outside checkout. A file-tool write inside the workspace, a subagent's transcript and an outside Git command remain proved only by the unit tests over recorded transcripts.
- **A shell command's write passes, as designed.** In the first Slugify run the resume turn wrote the same `NOTES.md` with `echo … > <path>` in a Bash call (the driver's prompt then didn't name a tool), and Stayed in the workspace passed. That is the PRD's table row "Any other shell command: Passes: Kiln doesn't see what it changes, and doesn't claim to", now seen on a real session. That run still stands as the one-repository add above; the stop and its clearing were done in the second. Its local worktrees were removed afterwards so the second run could use `.worktrees/slugify/`; its branches and pull requests (#2) remain on GitHub.
- **The confirmation is refused when there is nothing to confirm.** In an earlier attempt, abandoned because the driver passed the resume turn no prompt (its output wasn't kept), a tick sent while Stayed in the workspace hadn't failed got 409, "Stayed in the workspace hasn't failed, so there is nothing to confirm." That attempt's branches and worktrees were deleted before the run above.
