Kiln Build Preflight

Catch what would stop an unattended build before you walk away.

Kiln's start checks today confirm the documents, the plan and Kiln's own tools, but not what the build itself needs, so an expired sign-in or a test suite that cannot run on this machine stops the run hours later. This change has Kiln run the Enso Method's preflight check first, every time a run starts, and mark in the plan each phase that was planned as needing a person there. The goal is a run you can start and leave overnight. The linked documents are on an unmerged branch and open only once it is published.

01 / SECTION

Check the build before it starts

The preflight is a check, often several minutes long because it runs the project's tests, that every sign-in the plan needs works and will last the run, that this machine can build and test the project, and that nothing in the plan will stop the run without warning. It may fix some things itself, such as refreshing a sign-in, but it changes no file in the repository. It shows as a Preflight row at the top of the plan. When it finds nothing, Kiln carries straight on with no pause, and the row reads Ready with "Nothing to settle". If it ends without a report, Kiln carries on too, and the row shows a No report warning.

Key acceptance criteria & mockups

  • The preflight runs before anything else, every time you press Start or Continue, and when you resume a run whose preflight never finished. There is no setting to turn it off. Phases added while the run is underway get no preflight of their own. Source
  • A preflight that ends without a report does not hold up the run; its row warns that it ended without one. Source

02 / SECTION

When the preflight finds something

If the preflight finds something you need to settle, Kiln stops at Needs you before any work starts, while you are most likely still there. The page lists each item in the preflight's own words: a command to run, or one named thing that needs settling. Anything that takes more than a command, such as an authorization the requirements never recorded, is worked through in a conversation: the page gives the command that opens the preflight's session in a terminal. Kiln's own preflight changes nothing in the repository.

Key acceptance criteria & mockups

  • The page offers two controls. Check Preflight again runs a fresh check. Mark complete starts the build with the items as they are, and the Preflight row records that you did. There is no Reply box: the page gives the command to open the session in a terminal instead. Source

03 / SECTION

Phases that need you there

Some work has no scripted way to do it, such as a console with no API. The method plans that work into the earliest phases and marks each one as needing a person. Before you press Start, the plan shows a Needs you there marker beside each such phase; point at it to read why. These markers are the only heads-up: Kiln does not repeat the list elsewhere. On Documents found, a warning also appears beneath Allow early merges when a phase would stop the run because early merges are off.

Key acceptance criteria & mockups

  • A marked phase runs like any other: Kiln does what it can and never holds it back or pauses before it. The marker is only a heads-up. Source
  • When a marked phase does stop for you, a card at the top of the Needs you page says it was planned as needing you and why. Source
