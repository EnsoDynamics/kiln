DOCUMENTS FOUND · SETTINGS

Audit loops

After the planned phases close, the audits can send Kiln back to finish or to prove acceptance criteria. Each trip back is a loop. These set how many Kiln makes on its own.

Kiln fixes what the delivery audit finds up to 3 times. Each loop is one audit that finds unfinished criteria, then the phases Kiln builds for them. If a 4th audit still finds something, Kiln stops at Needs you. It never delivers work the audit says is unfinished.
After the test audit, Kiln runs up to 3 sessions of test fixes, each one a loop, and tells the 3rd it is the last. The audit itself isn't a loop, even when it fixes a few small gaps on the spot. If a test shows a criterion was never finished, that is build work and counts as a delivery audit loop.
After the last test audit loop
Kiln accepts the remaining Weak tests for you and lists them in test-audit.md and in the pull request. It stops and asks you when a criterion has no test at all, a test is failing, or a high-risk criterion is still Weak.
Nothing is accepted for you. Kiln stops at Needs you with what is left.

These can be changed while Kiln runs, like model, effort and keep-awake.
