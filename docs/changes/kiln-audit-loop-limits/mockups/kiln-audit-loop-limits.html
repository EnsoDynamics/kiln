DOCUMENTS FOUND · SETTINGS

Audit loops

After the planned phases close, the audits can send Kiln back to finish or to prove acceptance criteria. Each trip back is a loop. These set how many Kiln makes on its own.

Kiln builds what the audits find unfinished up to 3 times. Each loop is one audit that finds unfinished criteria, then the phases Kiln builds for them. If a 4th audit still finds something, Kiln stops at Needs you. It never delivers work the audit says is unfinished.
After the test audit, Kiln runs up to 3 sessions of test fixes, each one a loop, and tells the 3rd it is the last. The audit itself isn't a loop, even when it fixes a few small gaps on the spot. If a test shows a criterion was never finished, that is build work and counts as a delivery audit loop.
After the last test audit loop
You say: “I accept the remaining Weak rows after the last test audit loop.” Kiln quotes that to the last session and to any test audit after it. It stops if anything else is left: a criterion with no test, a failing test, a high-risk criterion still Weak, or test work saved for later. A criterion found unfinished goes back to building first, while delivery audit loops remain.
You accept nothing in advance. Kiln stops at Needs you with what is left.

These can be changed while Kiln runs, from the page or the command line, like keep-awake.
