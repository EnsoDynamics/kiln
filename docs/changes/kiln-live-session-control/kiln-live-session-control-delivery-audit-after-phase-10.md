## Confirmed missing part and sibling check

`Engine.runProcess` checks `requireTakeoverReturn` and `transcriptMissing` before creating the resumed process (`src/engine/engine.ts:2603–2619`). `runSessionProcess` then starts the process, records PID/start identity and awaits `beforePrompt`. That callback (`engine.ts:2644`) captures local Git/report material, awaits `takeoverBecameComplete` → `doneCheck`, awaits `requireNoTerminal` with exact new-process self-exclusion, then compares only Git/report material. Neither that fingerprint nor the callback revalidates provider history. On success, `src/session/claude-session.ts:367–370` immediately supplies the first user prompt.

Consequently, loss/replacement of saved history during those asynchronous checks has no final usable-history guard. The requirements expressly place that revalidation before the first prompt/effect. This is a source-reachability finding, not a newly executed provider failure or a claim that the provider always loses already-loaded context.

The shared path covers browser Resume and stopped reply, bot Resume/Reply, phase/delivery-audit/test-audit identities and reviewed uncertain-delivery return. Initial unheld launch is outside this missing takeover/return part. Release correctly repeats `requireHistory` after `requireNoTerminal` in `reconcileTakeoverOnce`; Verify correctly repeats it through `recordDone.finalTakeoverCheck` → `requireTakeoverReturn`. Neither sibling needs its Phase 10 repair undone or reopened.
