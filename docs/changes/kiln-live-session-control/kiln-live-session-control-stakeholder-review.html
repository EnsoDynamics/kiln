01 / SECTION

Steer the current work or choose when to pause

Open Control live session from the running activity. Send an instruction beside its output, or compare the two pause choices in the same view.

Key acceptance criteria & mockups

  • Send message reaches the displayed running conversation without restarting it. Its receipt distinguishes sent, confirmed received and uncertain delivery; it never proves Claude carried out the instruction. AC-MSG-01–04
  • Pause & take over lets the current operation finish, then stops before more substantive work. The phase or audit may remain unfinished. The terminal command is available only after Kiln releases its attempt and tracked work. AC-TAKE-01–05
  • Pause after this phase or audit lets the whole activity finish, including commits, pushes and required checks, before waiting. Cancelling that request never cancels takeover or resumes stopped work. AC-LIVE-03/04

Deliver live controls for Claude phases and audits first?

This bounded change covers Claude implementation phases, delivery audits and test audits. Codex and final-delivery sessions keep their current controls, with an explicit reason when live controls are unavailable.

Why this is proposed

Doug requested live control of those three Claude activities and continuing the same conversation in a terminal. Existing support for ordinary Codex hand-back does not establish equivalent live controls. Including Codex would enlarge this change beyond the request's evidence. Example: A running Claude test audit offers both live actions; a Codex test audit retains its existing deferred pause and recovery controls. Impact if wrong: MEDIUM — Provider parity adds investigation, design and release evidence before these controls can ship for every run.

02 / SECTION

Continue in the terminal, then hand the work back

Copy the command for the same saved conversation after Kiln says it is ready. Exit Claude before using the existing Back from your terminal? choices.

Key acceptance criteria & mockups

  • Resume lets Kiln finish the same activity with the terminal conversation intact. Unfinished or uncommitted work alone does not prevent it. If the activity is already complete, Kiln asks for an explicit advance choice instead. AC-BACK-01/02
  • Verify & advance freshly checks the real phase or audit completion rules; it does not finish work, commit or push to create a pass. Required audits, delivery checks and any separately requested pause remain in force. AC-BACK-03/04
  • Uncertain messages hold progression and are never resent automatically. Review each message in the conversation and acknowledge it, then explicitly Resume or Verify; acknowledgement alone starts nothing. AC-MSG-03/05
  • Messages grant no new merge, deployment, spending or workspace permission. When bot control and this change are both available, message and take-over commands follow the same targeting, receipt and hand-back rules. AC-MSG-04; AC-BOT-01/02
