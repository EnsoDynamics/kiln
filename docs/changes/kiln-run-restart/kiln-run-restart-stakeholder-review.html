Kiln Run Restart

When a phase stops, Kiln says which kind of stop it is and offers a button that has Kiln carry on, unless Kiln found a safety problem with a Codex session. You can also reset Kiln for a PRD, and start Kiln on a branch that already exists.

Kiln runs an AI agent, Claude Code or Codex, through each phase of a PRD, one session at a time. Today a stopped phase can leave you at a dead end. In a recent run, Phase 1 stopped before writing any code. The page said the agent's conversation couldn't be recovered, with no reason and no way to try again. It showed failing completion checks for a phase that had never started, and offered a button that would have skipped the phase. There was no way to have Kiln continue the phase or begin again, so the only way out was stopping Kiln and clearing its saved state, worktree and branch by hand. This change makes each stopped phase say what happened and offer a button that has Kiln carry on, adds a reset that makes Kiln forget its progress on a PRD, and lets Kiln start on a branch that already exists. A bot, meaning an automated agent driving Kiln through its command line, can do most of this too. Stops during the final audits and delivery are not part of this change. Every assumption behind it has already been answered, so there is nothing to confirm here: your feedback on the requirements and screens below is what's asked.

01 / SECTION

Start on a branch that already exists

Today Kiln's first screen, Documents found, always cuts a new feature branch from the base branch (the branch work starts from and is delivered back into, such as develop), and refuses a branch name that already exists. So phases you built yourself on a branch of your own, or a branch Kiln was using before a reset, can't be handed to Kiln. The screen gains a Start from choice. With an existing branch, Kiln reads the phase plan from that branch and skips the phases already closed there (each finished phase's own document marked closed in the plan), starting at the first open one. A branch is untouched when it has no commits that its base branch lacks and nothing uncommitted.

Key acceptance criteria & mockups

  • The first screen asks whether to start from a new feature branch or from a branch that already exists. When a branch with the name Kiln would give this PRD already exists, that branch is selected for you. Source
  • Kiln's sessions only add commits to the chosen branch and push them; Kiln never resets or force-pushes it. The final pull request is the branch's open one into the base branch, or a new one, and the screen says so before you start. Source
  • Apart from its sessions adding commits, Kiln itself moves a branch in one case only. An untouched branch that is behind its base branch gets an offer, ticked by default, to bring it up to date before the session starts, on the first screen and on a stopped phase's page. Kiln then moves the branch forward to the base branch's latest commit and pushes it; the branch has nothing of its own to lose. Source
  • If bringing the branch up to date fails, no session starts, and Kiln says why. Source
  • A bot's command that starts or resumes a stopped phase brings an untouched branch up to date the same way, unless the command is told to leave the branch as it is. Source
  • Kiln never brings a branch up to date when it has commits of its own or uncommitted changes; merging the base branch into it is left to you or a session. Source · 2

02 / SECTION

When a phase stops: which kind of stop, and always a way on

A phase can stop in three ways, and today's page treats them alike. Kiln couldn't start the agent at all. The agent ran but built nothing. Or it built something and needs your input. A phase's work is its commits since it began, apart from any brought in from the base branch, plus its uncommitted changes. A phase with neither has built nothing. When Kiln couldn't start the agent, the page offers Start Phase N again. Otherwise you can reply on the page, and Kiln resumes the agent's saved conversation with your reply. Sometimes that saved conversation can't be reopened, for example because it is missing or unreadable, or because its file could be changed by other accounts on the computer, so Kiln won't hand it back to an agent working unattended. Then the page offers Send reply & continue Phase N instead. It starts a new session that is given your reply, if any, the agent's last message and the work so far. The page says why the conversation can't be reopened, and Check again checks whether it now can. A bot can use Start Phase N again and Send reply & continue Phase N through commands, with no confirming step.

Key acceptance criteria & mockups

  • A stopped phase's headline says which case it is: Kiln couldn't start Phase N; Phase N stopped before building anything, with how long its latest conversation ran; or Phase N needs your input. A phase paused for takeover, or waiting on a message Kiln isn't sure was delivered, keeps its current page unless its session has ended and its conversation can't be reopened, and stops during the final audits or delivery keep their current pages. Source · 2
  • Kiln starts a new session only when the saved conversation can't be reopened; when it can, your reply resumes that same conversation. If Kiln has found a safety problem with Codex (an earlier Codex session's cleanup or dispatch is unresolved), then whatever else holds, the page offers no reply that has Kiln carry on: it says the conversation can't be recovered and offers instructions for a fresh session in your terminal. Source
  • A phase that built nothing shows Nothing to check yet in place of its completion checks (the checks Kiln runs to decide a phase is done), until you press Check Phase N anyway. Once the checks have run, their results show, Mark complete is offered when a check still fails so you can advance anyway, and the page says the phase built nothing. Source

03 / SECTION

A phase paused for takeover whose conversation can't be reopened

Pause & take over is for when you want to work with the agent yourself. Kiln stops the running phase at a safe point, so you can continue the same conversation in your terminal. The phase then waits for you; Kiln calls this held. A message you sent the running agent, when Kiln can't confirm it was delivered, puts a phase in the same waiting state. Normally the wait ends when Kiln can safely reopen the saved conversation. Today, if that conversation can't be reopened, the wait never ends and the phase is stuck.

Key acceptance criteria & mockups

  • When a held phase's session has ended and its saved conversation can't be reopened, the page offers Send reply & continue Phase N, which starts a new session for the phase, beside instructions for a fresh session in your terminal. It says why the conversation can't be reopened, with Check again. Source
  • Starting that new session ends the wait, without the old conversation ever being reopened. So does advancing when Kiln finds the phase already complete and you choose to move on. Source
  • Each message Kiln isn't sure was delivered is shown above the two choices and must be acknowledged before Send reply & continue Phase N works. Such a message reaches the new session only if you include it in your reply. Source
  • Both choices are unavailable, with the reason, while the agent is still open on that conversation in your terminal or work the paused session started is still running. Source

04 / SECTION

Reset Kiln for a PRD, in the browser or by a bot

When nothing on the page fixes the situation, a reset makes Kiln forget its progress on the PRD and go back to its first screen, without you needing to know where Kiln keeps anything. Kiln then behaves as if it had never run the PRD, but your branch, worktree, commits and pull requests are kept. The first screen opens as on a first visit; when the branch Kiln was using has the name Kiln gives this PRD's branch, it is already selected, so you can go on from it. Once a PRD has started, every screen ends with a line saying what reset does and a Reset Kiln for this PRD button. While Kiln is working, the button is unavailable, and the line tells you to stop the session first with Pause & take over, or to pause after the current phase or audit and reset once it ends.

Key acceptance criteria & mockups

  • Reset asks first. The confirmation says the reset can't be undone and lists what Kiln forgets: which phase it was on and each phase's result; its sessions and their output; stops, completion waivers (where you had Kiln advance although a check failed) and audit results; its settings for the PRD; and its record of earlier deliveries (work already merged into the base branch before the end, which a PRD can allow for deployment). It also lists what stays exactly as it is: the feature branch and its commits, the worktree and its uncommitted files, any pull request, and the phases closed in the plan on the feature branch. Source
  • A reset touches nothing in git: no branch, worktree, commit, pull request or document changes in any repository. Source
  • A bot can reset with a command, which acts at once with no confirming step; it is refused whenever the button is unavailable. The command's help is the warning: it says the reset can't be undone, what Kiln forgets, and that nothing runs again until someone opens Kiln in the browser and presses Start. Source
  • Not part of this change: deleting a branch, worktree or pull request (you do that in Git or GitHub), resetting one repository of a PRD that spans several, and undoing a reset. Source
