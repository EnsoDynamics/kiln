Kiln Find Repositories Anywhere

Kiln finds a plan's repositories wherever they are checked out, and one plan runs unchanged on every computer.

A plan here is a PRD and its phase documents. Today Kiln builds a plan across several repositories only when every one is checked out in the same folder as the main repository, the one holding the plan, under the folder name the plan uses. All screens use fictional sample data.

What we’re building

If any of these is wrong, say so before reading on. The rest of this review is detail within them.

  1. A plan names each repository by the path in its remote address, such as acme-labs/admin, which says which repository it is and is the same on every computer. Nothing about one person's computer goes into a shared document. Source
  2. Kiln finds each repository's checkout itself, wherever it is kept under your home folder, by looking outward from the main repository. There is no setting for where code lives. Source
  3. When Kiln can't find a checkout, or finds more than one, it asks you once and remembers the answer on that computer only. Source
  4. Plans that name a repository by its folder name keep working exactly as they do today. Source
  5. The Enso Method's phase-split skill writes repository names this way too, so a plan works for anyone, whether it is run by hand or in Kiln. Source

Not included

  • A setting or file that says where repositories are kept.
  • Cloning. Kiln works only with repositories already on the computer.
  • Following a link (a shortcut to a folder) to reach a checkout, or searching for a repository by its folder name.
  • Delivering to a host other than GitHub, where Kiln already opens its pull requests. A plan that names another host stops at the start, and a checkout found on one is never used.
  • Rewriting plans already written. Their folder names keep working.
  • Recovering when a repository's checkout is moved or deleted after work on it has started.
  • Starting Kiln from a folder above the repositories.

01 / SECTION

Name a repository the same way everywhere

Each phase document lists the repositories its phase changes on its Repositories line. A repository's address path is the part of its remote address after the host, without .git: acme-labs/admin for git@github.com:acme-labs/admin.git.

Key acceptance criteria & mockups

  • Kiln refuses a full remote address, or a path on one computer such as ~/code/admin, on that line, and says to write the address path instead. Source
  • phase-split, which people also run by hand on any host, writes the host before the path only when two of a plan's repositories share a path on different hosts. Source

02 / SECTION

Find each checkout

Before Start, Kiln looks for every repository a plan names by address path, matching a checkout by its remote address, never its folder name. It looks beside the main repository first, meaning in the same parent folder, then outward.

Key acceptance criteria & mockups

  • The search never goes above your home folder, and only a set depth below it, so a checkout on another disk is asked about rather than found. Source
  • The search never makes the computer ask permission to read a folder. A repository kept in a protected folder, such as Documents, is asked about instead. Source
  • When the search finds exactly one checkout, Kiln uses it and shows its folder on the repository's row, with no way to pick another there. Source · 2

03 / SECTION

Answer once when Kiln can't tell

Kiln asks when its search finds no checkout of a repository, or more than one. You answer by picking a checkout Kiln found or by giving a folder.

Key acceptance criteria & mockups

  • Once every other start check passes, Kiln asks on that repository's row on Documents found, rather than failing or prompting in the terminal. Start waits for every answer. Source
  • Only a repository's own checkout on GitHub counts, found or given: never a worktree, a submodule or a link, so a repository kept only as a worktree can't be used. Source · 2
  • One answer serves every plan on this computer that names that repository, so you are asked once per computer, not once per plan. Source
  • The row's Change link replaces a remembered answer only before Start. Once a plan's work in a repository has begun, the plan keeps that checkout. Source

04 / SECTION

When a repository comes up after Start

Once a plan has started, a repository Kiln can't place can still come up: a phase about to start names one, perhaps after an edit, or a session (the AI agent working on a phase) asks Kiln for one it needs.

Key acceptance criteria & mockups

  • That phase doesn't start. Its Needs you page asks Documents found's question, and the phase starts once that is answered and nothing else holds it. Source
  • Kiln tells the session it can't add the repository, and the session carries on. You're asked only if the phase stops for another reason, never for this alone. Source · 2
  • Once two of a plan's repositories share a final name, as acme/admin and acme-labs/admin do, both are shown by their whole path from then on. Source

ASK-004Confidence: 65%Impact: LowNo reply needed

When one checkout sits beside the main repository and another is farther out, does Kiln ask which to use rather than take the one beside it?

Yes. Whenever Kiln finds two checkouts of one repository that it can use, it asks which, even when one sits beside the main repository. You answer once on each computer.

Details and optional reply

Kiln searches every folder within reach each time, so a copy beside the main repository never hides one farther out. For example, with the main repository at ~/code/acme/product, an old clone beside it at ~/code/acme/storefront-old and the one you work in at ~/code/acme-labs/storefront, Documents found lists both and asks.

If you choose otherwise: A checkout beside the main repository is used without a word, as today, and Kiln searches no farther. It asks only when none is beside it and it finds more than one farther out.

For asking: your decision of 21 November 2026 says that when Kiln finds two checkouts of one repository it asks instead of guessing, and it names no distance. For using the one beside: the same decision says Kiln looks beside the main repository first, as today, and today a checkout there is used without a question. Under the proposed answer, looking beside first no longer changes which checkout is used. What asking costs: one question per computer. Until it is answered, a session's request for that repository is refused, and a phase that comes to name it after Start stops for you, so an unattended run waits where it would otherwise carry on. What a wrong silent pick costs: little, and the case is rare (one such pair among 302 checkouts on one computer). The work branches from the base branch on GitHub and is pushed there either way, so the same code is delivered; only the working copy is made from the old clone.
