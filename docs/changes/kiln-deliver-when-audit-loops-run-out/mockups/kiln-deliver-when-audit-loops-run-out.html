1. Audit loop settings, before Start

Two limits, each 4 by default, and nothing to choose about what happens at a limit. The run's settings and kiln settings show the same two during a run. Covers AC-CHOICE-01.

Audit loops

After the planned phases close, two audits check the work. Whatever an audit finds, Kiln builds or fixes, and that is one loop. These set how many loops of each Kiln makes. After the last one, Kiln moves on without auditing again.

Delivery audit loops, at most  4

The delivery audit checks that every acceptance criterion is built. A loop is building the phases it adds. After loop 4, Kiln goes on to the test audit.

Test audit loops, at most  4

The test audit checks that the tests would notice if a criterion broke. A loop is building the phases it adds, if any, then one session of test fixes. After loop 4, Kiln opens the pull request.

Kiln tells the last test loop, in your words: “I accept the remaining Weak rows after the last test audit loop.”

Both can be changed while Kiln runs, from the page or the command line.
