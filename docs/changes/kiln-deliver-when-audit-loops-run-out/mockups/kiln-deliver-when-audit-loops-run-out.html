1. Audit loop settings, before Start

Two limits, each 4 by default, and nothing to choose about what happens at a limit. Each loop is one run of that audit. The run's settings and kiln settings show the same two during a run. Covers AC-CHOICE-01.

Audit loops

After the planned phases close, two audits check the work. Each run of an audit is one loop; Kiln builds or fixes whatever it finds. These set how many loops of each Kiln makes. After the last one, Kiln moves on without auditing again.

Max delivery audit loops  4

The delivery audit checks that every acceptance criterion is built, and Kiln builds the phases it adds. Each run of the audit is one loop. After the phases from loop 4 are built, Kiln goes on to the test audit.

Max test audit loops  4

The test audit checks that the tests would notice if a criterion broke, and Kiln builds or fixes what it finds. Each run of the audit is one loop. After the work from loop 4 is done, Kiln opens the pull request, after a delivery audit if one is left.

Both can be changed while Kiln runs, from the page or the command line.
