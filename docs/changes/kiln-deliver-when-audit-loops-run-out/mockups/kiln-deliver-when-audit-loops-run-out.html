1. Audit loop settings, before Start

Two limits and one choice for both audits. The run's settings show the same three during a run. Covers AC-CHOICE-01.

Audit loops

After the planned phases close, two audits can send Kiln back for more work. Each trip back is a loop. These set how many Kiln makes, and what it does when they run out.

Delivery audit loops, at most  3

The delivery audit checks that every acceptance criterion is built. A loop is one round of building what it finds unfinished.

Test audit loops, at most  3

The test audit checks that the tests would notice if a criterion broke. A loop is one session of test fixes.

When the loops run out

One choice for both audits.

Deliver, and tell me what is left

Kiln opens the pull request and lists at the top any criteria still partly built and any tests still Weak. The phases an audit added stay in the plan, so you can continue later.

For the test audit you say: “I accept the remaining Weak rows after the last test audit loop.”

It still stops for something serious: a criterion not built at all; after the last test audit loop, test work still saved or a test only you can accept by name (no test, a failing test, a high-risk criterion still Weak, or a row the audit is stuck on); or anything else an audit lists that the work can’t go on without.

Always stop and ask me

Kiln stops at Needs you with what is left, and opens no pull request until you answer.

These can be changed while Kiln runs, from the page or the command line.
