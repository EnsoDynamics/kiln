**Weak**
- **AC-CHOICE-02** (high risk): 10 of 11. No test accepts a limit changed on the page during a run: every accepted mid-run change calls `engine.changeSettings` directly, so the `/api/settings` mapping of `auditLoops` during a run is untested. The combination "delivery raised after its last loop, test closed, goes on to the pull request" is covered only by analogy. Fix: in "refuses a limit below the runs already made, accepts the floor…", POST `/api/settings` `{auditLoops:{deliveryLimit:2}}` for the accepted change and assert 200, the saved limit and the same outcome. Add a move-on case with `testLimit: 1` that raises delivery to 2 during the test audit after a gap, expecting kinds `[delivery, test, delivery]` and completion.
- **AC-ITEM-01** (high risk): 14 of 15. The audit prompt's item-kind definitions are checked only by key name (`src/engine/engine-helpers.test.ts` › "states Kiln's version-2 report contract…"), so a wrong definition or effect ("below 20%", "It holds the run", "Kiln stops at once") would go unnoticed. Fix: assert each kind's definition sentence from `prompts/audit-session.txt`, and render the delivery audit prompt once as well.
- **AC-ITEM-02:** 7 of 10. Three things are untested: that a `critical_next_step` item with no `waitsOn` is refused, that a stop or hold item with an empty `problem` is refused, and that the status line names the step that listed the items (pull request step and audit step). Fix: add two rows to the refusal `it.each` in `src/audit/admission.integration.test.ts`, and assert the header for a hold-stop snapshot (names "Final delivery") and for an audit item stop (names the audit and its loop).
- **AC-LAST-05:** 1 of 3. Nothing pins that Kiln marks no criterion built and closes no phase its own sessions did not. Fix: a move-on case with `testLimit: 1` where the test audit reports `continue_test` and the fix session passes with a `test` item. Assert the PRD's criterion checkbox is still `- [ ]`, that every phase with `doneAt` has non-empty `sessionIds`, and that both `delivered.forYou` and `kiln status` list the test gap. Add `sessionIds` assertions to the existing added-phase tests.
- **AC-LAST-03:** 5 of 6. The rule that work from phases a marked-complete audit appended is audited again only while a loop is left is checked only through the offer's forecast. No test presses Mark complete and follows the route. Fix: extend "Mark complete's next step respects a closed kind" to waive-and-advance and assert the audits that ran and `completedAt`. Add a `deliveryLimit: 1` case whose delivery audit reports `completion_phases` and is marked complete, and assert its phases are built and no second delivery audit runs.
- **AC-LEFT-02:** 4 of 5. Nothing checks that the heading is unchanged on a delivered run: no test renders the Complete header with `snapshot.delivered` set. Fix: in `view/src/screens/completion-for-you.test.ts` or `view/src/lib/progress.test.ts`, set `delivered` on `completeSnapshot()` and assert the header label is still "PR ready for review".
