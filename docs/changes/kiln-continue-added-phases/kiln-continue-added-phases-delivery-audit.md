## Confirmed gap and sibling checks

`src/engine/plan-reconciliation.ts::planSourceFromDocuments` constructs aliases only for a phase's bare filename and `./filename`; `normalizedScope` exact-matches a link's destination against that map. Both saved-checkout and Git-object document readers instead decode and normalize valid repository-relative destinations. Updating a completed sibling's link after a harmless phase-file rename can therefore change its scope hash and block discovery/continuation as unresolved earlier work.

A fictional in-memory probe against the existing compiled `planSourceFromDocuments` and `completedScopeProblems` exports kept phase IDs, titles, text, dependencies and closure fixed while renaming phase 2 and updating phase 1's link. Bare/`./` destinations yielded no scope problem. `../comet/filename`, `x/../filename` and percent-encoded filename destinations yielded the false error `Phase 1: previously completed scope was removed, reopened, split or materially changed.` Both rounds independently reproduced the same class of defect; the main assessor reproduced relative and encoded siblings. The shared external-completion and active/legacy scope callers also need consistent semantics. Meaningful target/query/fragment changes and path protections must remain effective.

The design's Plan Identity and Comparison explicitly requires resolving phase-document links to phase IDs before comparing renames. This is a malfunction, not a deliberate alternative product behavior. The conflict check shortlisted all eleven repository PRDs by title/summary and read relevant active plan/history criteria; no later-built criterion changes rename equivalence. Completion Audits AC-LOOP-01/AC-RUN-03, Kiln v1 AC-RUN-01/04, bot AC-SEE-02 and development-delivery recovery requirements preserve their separate scheduling/currentness/evidence rules. AC-CONTINUE-03 remains the owner; no supersession amendment or business assumption is needed.
